## 一、已确认的核心决策

| 编号 | 问题 | 你的选择 | 含义 |
|---|---|---|---|
| D1 | 应用端形态 | **A. 电脑桌面软件 + 网页端** | 第一版优先 Windows 电脑；网页端同时可用；手机原生 App 不在第一版 |
| D2 | 使用范围 | **B. 同一局域网/办公室多人使用** | 一台主机保存数据，同一网络内的用户通过浏览器或客户端访问；公网访问不在第一版 |
| D3 | 钥匙保管方式 | **C. 先服务器端加密，架构预留端到端升级** | 第一版由服务器保管钥匙；能防硬盘/备份被偷，但不声称能防服务器最高管理员；以后可升级 |
| D4 | 整体技术路线 | **A. Python 后端 + React 网页 + 桌面客户端外壳** | 前后端分离；桌面端复用网页界面；具体框架在第 1 阶段 spec 中确认 |
| D5 | 下载策略 | **A. 授权即可下载，全程留痕** | 被授权用户可以下载文件；每次下载都记录审计；下载后不再受系统保护 |

## 四、第一版范围冻结

### 包含

- 本地/局域网部署，单台主机。
- 网页端 + Windows 桌面客户端外壳。
- 管理员/普通用户两种角色。
- 用户组管理、按组授权、按人单独授权。
- 文件加密存储、文字秘密（网站/数据库密码等）加密存储。
- 被授权用户查看/解密；授权撤销立即生效。
- 文件下载 + 全程审计。
- 管理员不自动拥有全部内容解密权。
- 审计日志、加密备份与恢复。
- 公开部署前的安全基线和安全说明。

### 不包含

- 云端对象存储、多租户、跨组织共享。
- 原生手机 App（第一版只提供手机浏览器可用的网页）。
- 公网直接访问（需要时单独做 HTTPS/域名/VPN/防火墙阶段）。
- 端到端加密（架构预留，第一版不实现）。
- 双因素认证、单点登录、在线预览/编辑、文件水印/DRM、全文检索、版本历史。
- 用户自助注册、对外分享链接。

## 五、已接受的关键限制

这些限制在可行性报告和需求分析中已说明，你选择推荐方案即视为已知情：

1. 被授权用户解密后可拍照、另存、转发；系统只能通过留痕、下载控制和及时撤销降低风险，不能绝对阻止。
2. “文件放本地”指放在运行服务的主机上，不是每个用户自己的电脑；主机停机则其他人无法访问。
3. 第一版是服务器端加密，理论上拥有服务器最高权限的恶意管理员可以解密；要防住需后续端到端加密。
4. 主密钥/备份口令丢失可能导致数据永久无法恢复；必须做备份并离线保存恢复材料。
5. 加密不替代杀毒、系统更新和备份；勒索软件、硬盘损坏仍需靠备份兜底。
6. 第一版不做高可用；主机故障会中断服务，但数据应能通过备份恢复。

## 六、变更控制

- 每个阶段先写 spec，你审阅通过后才开始开发。
- 开发完成后提供可运行版本和验收演示；你确认后再进入下一阶段。
- 新需求先记录，不直接插队；评估影响后决定放入当前阶段还是后续版本。
- 涉及数据结构、密钥、权限、备份策略的变更，必须单独说明迁移和回滚方案。
- 不删除、不覆盖你的数据；任何破坏性操作都要先告知并取得同意。
