> **一句话**：让管理员能查询“谁在什么时候做了什么”，并提供带独立口令的加密备份包、备份验证和安全恢复流程；同时做一次部署安全加固。
>
> **数据安全说明**：本阶段只新增审计记录表和备份记录表，不修改现有账号、用户组、条目、授权和加密内容。恢复备份会覆盖当前数据，因此必须二次确认，并自动先把当前数据复制到安全目录；不会静默覆盖。

## 一、本阶段目标

1. 管理员可以在网页中查询审计记录：时间、操作人、操作、对象、结果、来源地址。
2. 关键操作写入数据库审计表，覆盖登录、账号、用户组、授权、条目、内容查看/下载、保险箱解锁和备份恢复。
3. 审计记录不包含密码、主密码、密钥、明文内容或原始文件名。
4. 管理员可以在网页创建加密备份包，包含数据库快照、密文文件、主密钥文件和清单。
5. 备份包使用**独立备份口令**加密；备份口令不保存在服务器、数据库或 `.env` 中。
6. 管理员可以在网页验证备份包是否完整可读，不需要恢复。
7. 提供命令行恢复流程：先校验、再自动备份当前数据、最后替换；失败可回滚。
8. 主页显示最近一次备份时间和到期提醒。
9. 提供部署安全检查命令，检查调试开关、密钥、目录权限、磁盘空间和备份状态。
10. 审计记录默认保留 180 天，到期自动清理并记录清理动作。
11. 保持第 1–6 阶段功能不变；不改变加密格式、授权规则和现有数据结构。

## 二、前置状态与硬约束

- 第 1–6 阶段已验收；真实数据库已有账号、条目、授权、密钥和加密内容，必须保留。
- 本阶段**只新增表**；迁移前先做数据库备份并记录迁移前后各表数量。
- 恢复备份是破坏性操作：必须二次确认、必须自动保留当前数据的安全副本、失败必须能回滚。
- 备份口令**不会**被保存；丢失备份口令等于备份包无法打开。主密码仍需另行保管，两者缺一不可。
- 审计记录和备份清单都不能写入密码、主密码、密钥、明文内容、原始文件名或文件内容。
- 审计记录只能通过数据库维护清理，网页不提供修改或删除入口。
- 默认仍只在本机使用；是否开放局域网由 D7-7 单独决定，不会默认开放。
- 不引入云端备份、自动上传或第三方审计服务。

## 三、需要你拍板的关键决定

### 3.1 D7-1：审计记录存在哪里？

| 选项 | 像什么 | 优点 | 缺点 |
|---|---|---|---|
| **A. 专门的审计表 + 管理页面（推荐）** | 在数据库里单独放一本“来访登记簿”，网页可按人、时间、操作筛选 | 查询快、可按条件筛选、可分页；与业务数据一起备份；不依赖日志文件格式 | 新增一张表；审计写入会增加一点数据库操作 |
| B. 解析现有日志文件 | 继续写日志，再做一个“日志阅读器” | 不改数据库；日志本来就有 | 日志是给人排查用的，格式不稳定；筛选慢；日志轮转会丢记录；无法可靠分页 |
| C. 只写日志，不做查询页面 | 记录照写，但只能打开日志文件看 | 工作量最小 | 管理员无法方便查询；不满足“可查询审计”的目标 |

**推荐：A（专门的审计表 + 管理页面）。**

说明：

- 现有 JSON 日志继续保留，用于排查服务器问题；审计表用于“谁做了什么”的查询和举证。
- 审计表只存结构化字段和简短标签，不存密码、密钥或内容。
- 日志轮转只保留最近若干 MB，不能当作长期审计记录；审计表按 180 天保留更可靠。

### 3.2 D7-2：审计记录什么时候写入？

| 选项 | 像什么 | 优点 | 缺点 |
|---|---|---|---|
| **A. 操作发生时同步写入（推荐）** | 办完一件事，当场在登记簿上写一笔 | 记录及时、可靠；操作成功就一定有记录 | 会多一次数据库写入；数据库故障时写不进去 |
| B. 先排队，后台异步写入 | 先把纸条丢进箱子，稍后统一登记 | 页面响应更快 | 服务器突然断电可能丢记录；实现更复杂 |
| C. 只依赖现有日志 | 不额外写数据库 | 改动最小 | 无法保证审计表完整；查询困难 |

**推荐：A（同步写入）。**

说明：

- 审计写入失败只记录警告，不阻断原本已经成功的业务操作；但会在日志中留下“审计写入失败”。
- 对登录失败、解锁失败、永久删除、备份创建和恢复等关键动作，审计记录尤为重要。

### 3.3 D7-3：备份包包含什么、怎么保护？

| 选项 | 像什么 | 优点 | 缺点 |
|---|---|---|---|
| **A. 加密备份包：数据库快照 + 密文文件 + 主密钥文件 + 清单，使用独立备份口令（推荐）** | 把四件套里除主密码外的三样装进一个带密码的保险箱 | 一份文件即可完整恢复；备份包被拿走也打不开；能校验完整性 | 备份口令丢失则备份包无法打开；创建和验证需要输入口令 |
| B. 普通 ZIP，不加密 | 把文件装进纸箱，不锁 | 简单、速度快 | 备份包被拿走就能看到数据库和密钥文件；不符合安全要求 |
| C. 只备份数据库 | 只抄一份账本 | 文件小 | 缺少密文和主密钥文件，无法恢复文件内容 |

**推荐：A（加密备份包，独立备份口令）。**

说明：

- 备份包内容：数据库一致性快照、`data/vault/objects/` 下的密文、`data/keys/master.key.json`、`manifest.json` 清单。
- 不包含 `.env`、日志、临时文件和旧备份；这些不影响加密内容恢复。
- 清单记录应用版本、创建时间、各文件 SHA-256 和大小，不记录任何秘密。
- 备份包格式为 `.efbak`，整个压缩包用 AES-256-GCM 加密；口令通过 Argon2id 派生密钥。
- **四件套仍然成立**：数据库、密文、主密钥文件在备份包里，主密码只在你的记忆中。没有主密码，恢复后仍无法解密内容。

### 3.4 D7-4：怎么恢复备份？

| 选项 | 像什么 | 优点 | 缺点 |
|---|---|---|---|
| **A. 命令行恢复脚本 + 二次确认 + 自动安全备份（推荐）** | 由服务器操作员在服务器上执行，先抄一份当前数据再替换 | 权限边界清楚；不会误点网页就覆盖；失败可回滚 | 需要打开 PowerShell；不能在网页上一键恢复 |
| B. 网页上传备份包恢复 | 在浏览器里选文件、点恢复 | 操作直观 | 网页误操作风险高；上传大文件慢；覆盖正在使用的数据库容易损坏 |
| C. 只提供手工替换文件说明 | 自己停服务、复制文件 | 不需要写代码 | 容易漏文件、漏步骤；没有校验和回滚 |

**推荐：A（命令行恢复 + 二次确认 + 自动安全备份）。**

说明：

- 恢复脚本会先检查服务器是否已停止、备份包是否能解密、清单和哈希是否一致。
- 通过检查后，先把当前数据库、密文和密钥复制到 `data/backups/pre-restore-时间/`，再替换。
- 任何一步失败都会自动回滚；不会出现“删了旧数据又没有新数据”的情况。
- 恢复完成后保险箱自动处于锁定状态，管理员用恢复时的账号登录并重新输入主密码。

### 3.5 D7-5：备份什么时候做？

| 选项 | 像什么 | 优点 | 缺点 |
|---|---|---|---|
| **A. 手动备份 + 到期提醒（推荐）** | 管理员点按钮备份；超过 7 天没备份主页提醒 | 备份口令不需要保存；安全边界最简单 | 需要管理员记得点；忙的时候可能忘记 |
| B. 手动 + Windows 计划任务自动备份 | 让计划任务每天定时执行 | 不容易忘 | 无人值守时必须把备份口令保存在本机，降低安全性 |
| C. 只手动，不做提醒 | 完全靠管理员自觉 | 最简单 | 很容易长期没有备份 |

**推荐：A（手动备份 + 到期提醒）。**

说明：

- 无人值守的定时备份必然要把备份口令存到某处；一旦服务器被入侵，攻击者可能同时拿到备份包和口令。
- 本阶段优先保证“备份口令不落地”；每天/每周的提醒会显示在管理员主页。
- 如果以后确实需要无人值守备份，会单独评估“用 Windows 凭据管理器保存口令”的方案，并明确风险。

### 3.6 D7-6：审计记录保留多久？

| 选项 | 像什么 | 优点 | 缺点 |
|---|---|---|---|
| **A. 180 天，到期自动清理并记录（推荐）** | 登记簿保留半年，过期页归档清理 | 与项目默认值一致；数据库不会无限增长；清理动作本身也被记录 | 超过半年的记录不再可查 |
| B. 永久保留 | 登记簿一直留着 | 记录最完整 | 数据库持续变大；查询变慢；隐私暴露面增加 |
| C. 90 天 | 只留三个月 | 数据库更小 | 不满足项目已确认的“180 天起”默认值 |

**推荐：A（180 天）。**

说明：

- 保留天数可通过配置调整，默认 180 天。
- 清理由管理命令执行，可手动运行，也可在需要时加入计划任务；清理数量和最早/最晚时间会写入审计记录。
- 网页不提供“删除某条审计记录”的按钮。

### 3.7 D7-7：本阶段是否开放局域网？

| 选项 | 像什么 | 优点 | 缺点 |
|---|---|---|---|
| **A. 继续只在本机，先完成加固清单（推荐）** | 先把门锁、登记簿和保险柜都准备好，暂不打开大门 | 风险最低；不需要处理证书信任；本阶段能稳定交付 | 其他电脑仍不能访问；局域网多人使用要再走一步 |
| B. 开放局域网，必须 HTTPS（自签证书） | 打开大门，但要求每台电脑先安装证书 | 满足多人使用方向 | 要为每台电脑安装并信任证书；地址变化、证书过期都会导致客户端报错；排错复杂 |
| C. 开放局域网，使用 HTTP | 打开大门但不装锁 | 配置最简单 | 登录密码和内容在网络上明文传输，**不建议** |

**推荐：A（继续只在本机，先完成加固清单）。**

说明：

- 你最初选择的是“同一局域网多人使用”（D2-B），这个方向没有取消；但开放局域网需要证书、固定地址、防火墙和客户端信任一整套准备。
- 本阶段先把审计、备份、恢复和安全检查做扎实；局域网开放作为下一步单独确认，避免在安全基础没完成时先开网络。
- 如果你现在就需要同事访问，可以选 B；我会在 spec 里补充证书生成、每台电脑导入证书和防火墙配置步骤，工作量和排错难度都会明显增加。

## 四、角色与使用边界

| 操作 | 管理员 | 普通用户 |
|---|---|---|
| 查询审计记录 | 可以 | 不可以（返回 404） |
| 创建备份 | 可以 | 不可以 |
| 验证备份 | 可以 | 不可以 |
| 查询备份列表和备份提醒 | 可以 | 不可以 |
| 恢复备份 | 在服务器上执行命令行 | 不可以 |
| 查看系统安全状态 | 可以 | 不可以 |
| 删除审计记录 | 只能通过保留期清理命令 | 不可以 |
| 修改或删除备份文件 | 只能由服务器操作员在文件系统中处理 | 不可以 |

- 管理员的审计查询本身也会被记录（`audit.viewed`），避免“查看审计不留痕”。
- 审计记录中的操作人显示当时的用户名快照；账号后来改名或删除，历史记录仍可读。

## 五、技术设计

### 5.1 新增数据表

新增 Django 应用 `apps.audit`，包含两张表：

**AuditEvent（审计事件）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 自增主键 | |
| `created_at` | 日期时间，索引 | 事件发生时间（UTC 存储，界面按本地时区显示） |
| `actor` | 外键，可为空，删除时置空 | 操作人 |
| `actor_username` | 字符串 150，索引 | 操作人用户名快照 |
| `actor_role` | 字符串 16 | 当时角色快照 |
| `action` | 字符串 64，索引 | 例如 `login_succeeded`、`item_purged` |
| `target_type` | 字符串 32，可空 | `user`、`group`、`item`、`vault`、`backup` 等 |
| `target_id` | 整数，可空 | 对象编号 |
| `target_label` | 字符串 200，可空 | 标题/组名等管理标签，不含秘密 |
| `result` | 字符串 16 | `success`、`failure`、`denied` |
| `ip_address` | IP 地址，可空 | 来源地址 |
| `request_id` | 字符串 64，可空 | 与日志关联的请求编号 |
| `detail` | JSON，默认空对象 | 安全的结构化细节，例如新增/移除的组编号、失败原因代码 |

索引：`created_at`、`actor_username`、`action`、`(action, created_at)`。

**BackupRecord（备份记录）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 自增主键 | |
| `filename` | 字符串 255 | 备份文件名 |
| `size_bytes` | 整数 | 文件大小 |
| `sha256` | 字符串 64 | 加密备份包本身的 SHA-256 |
| `format_version` | 整数 | 备份格式版本 |
| `app_version` | 字符串 32 | 创建时的应用版本 |
| `created_at` | 日期时间 | 创建时间 |
| `created_by` | 外键，可为空 | 创建人 |
| `status` | 字符串 16 | `created`、`verified`、`failed` |
| `verified_at` | 日期时间，可空 | 最近验证时间 |
| `note` | 字符串 200，可空 | 简短说明 |

- 两张表都是新增表，不修改任何现有表。
- 备份记录只记录备份包本身的信息，不记录备份口令、内部文件或内容。

### 5.2 审计写入

- 新增 `record_audit(request, action, ...)` 辅助函数，统一补齐操作人、角色、来源地址、请求编号和时间。
- 在现有视图的成功/失败分支调用；保留现有日志调用，两者不互相替代。
- 审计写入使用独立的小事务；写入失败记录 `audit_write_failed` 警告日志，不阻断已经完成的业务操作。
- 所有 `detail` 字段必须是白名单字段（编号、数量、原因代码、文件名等），禁止直接传入请求体。
- 审计动作清单（首版）：

| 类别 | 动作 |
|---|---|
| 登录 | `login_succeeded`、`login_failed`、`login_blocked`、`logout`、`password_changed` |
| 初始化 | `setup_completed`、`vault_initialized`、`vault_unlocked`、`vault_unlock_failed`、`vault_locked` |
| 账号 | `user_created`、`user_updated`、`user_role_changed`、`user_disabled`、`user_enabled`、`user_unlocked`、`user_password_reset` |
| 用户组 | `group_created`、`group_updated`、`group_deleted`、`group_member_added`、`group_member_removed` |
| 条目 | `item_created`、`item_updated`、`item_archived`、`item_unarchived`、`item_owner_changed`、`item_trashed`、`item_restored`、`item_purged` |
| 授权 | `grant_group_added`、`grant_group_removed`、`grant_user_added`、`grant_user_removed` |
| 内容 | `text_saved`、`file_uploaded`、`text_viewed`、`text_revealed`、`text_copied`、`file_downloaded` |
| 备份 | `backup_created`、`backup_verified`、`backup_verify_failed`、`backup_restored` |
| 审计 | `audit_viewed`、`audit_pruned` |

### 5.3 审计查询界面

- 路由：`/admin/audit`，仅管理员。
- 筛选条件：关键词（操作人/对象标签）、动作类别、结果、开始日期、结束日期。
- 默认按时间倒序，每页 50 条，支持上一页/下一页。
- 列表列：时间、操作人（含角色）、操作、对象、结果、来源地址。
- 点击一行展开 `detail`，以键值对显示；不显示任何请求原文。
- 筛选选项接口返回当前动作类别，不返回用户密码等信息。
- 正常用户访问返回 404，与未授权内容一致。

### 5.4 备份包格式

备份文件扩展名 `.efbak`，整体结构：

```text
EFB1 魔数 + 版本
Argon2id 参数 + 盐
基础 nonce
加密的 ZIP 数据（分块 AES-256-GCM）
认证标签
```

- 口令通过 Argon2id 派生 256 位密钥；盐每次随机。
- ZIP 内部结构：

```text
manifest.json
db/db.sqlite3
keys/master.key.json
objects/<随机文件名>.vault
```

- `manifest.json` 记录：格式版本、应用版本、创建时间、数据库/密钥/每个密文的 SHA-256 和大小、条目与账号数量。
- 数据库使用 SQLite 在线备份接口生成一致性快照，不直接复制正在写入的数据库文件。
- 分块加密，支持大于内存的文件；每块使用不同 nonce，最后一块标记结束，防止截断。
- 备份文件权限尽量设为仅当前用户可读写；文件默认写入 `data/backups/`。
- 创建前检查磁盘剩余空间，至少需要预计大小的 1.5 倍；不足时拒绝并提示。

### 5.5 备份验证

- 输入备份口令，解密到临时目录，逐个校验清单中的 SHA-256 和文件是否存在。
- 只读校验，不替换任何现有数据；校验完成后删除临时文件。
- 验证失败给出原因（口令错误、文件损坏、缺少文件、格式版本不支持），不返回内部路径。
- 验证结果写入 `BackupRecord` 和审计记录。

### 5.6 恢复流程

命令示例：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/restore-backup.ps1 -File "data\backups\vault-backup-20261021-120000.efbak"
```

步骤：

1. 检查服务器未运行（默认端口 8000 没有监听）；如果仍在运行，停止并提示先关闭服务器。
2. 交互式输入备份口令（不回显、不写入历史记录）。
3. 解密到 `data/tmp/restore-时间/`，校验格式、清单和所有 SHA-256。
4. 显示备份创建时间、应用版本、账号/条目数量，要求输入 `RESTORE` 确认。
5. 将当前数据库、密文目录和主密钥文件复制到 `data/backups/pre-restore-时间/`，写清单。
6. 用校验过的文件替换当前数据；保留现有 `.env` 和日志。
7. 任一步失败：从 `pre-restore-时间/` 回滚并报告。
8. 成功后写入日志和审计记录 `backup_restored`；保险箱保持锁定。
9. 不自动重启服务器，由管理员手动启动并验证登录、解锁和至少一个条目。

安全约束：

- 不接受网页上传的恢复包；恢复只允许在服务器本机执行。
- 不删除旧备份和 `pre-restore-时间/` 目录；由管理员确认后再手工清理。
- 应用版本不同但格式版本一致时，默认拒绝；提供 `--allow-version-mismatch` 显式放行。
- 备份口令错误、清单损坏、磁盘空间不足时，不触碰当前数据。

### 5.7 备份界面与提醒

- 路由：`/admin/backup`，仅管理员。
- 页面内容：
  - 最近一次成功备份时间、距今多少天、备份文件列表（文件名、大小、创建时间、状态）。
  - “创建备份”表单：备份口令、确认口令、说明；提交后显示进度和结果。
  - “验证备份”按钮：输入备份口令，显示校验结果。
  - 恢复说明：显示命令行步骤和警告，不提供网页恢复按钮。
  - 备份口令与主密码的区别说明。
- 主页增加“备份状态”卡片：
  - 7 天内成功备份：绿色“最近备份正常”。
  - 超过 7 天或从未备份：黄色提醒，并给出“去创建备份”按钮。
- 备份创建和验证接口有限速，防止反复尝试口令。

### 5.8 审计清理

- 管理命令 `python manage.py prune_audit --days 180`，默认读取配置。
- 只删除 `created_at` 早于截止时间的记录；不删除最近记录。
- 删除前统计数量和时间范围，删除后写入 `audit_pruned` 记录（操作人为空，表示系统清理）。
- 提供 `--dry-run` 显示将删除多少条，不实际删除。
- 可在需要时由管理员手动运行；本阶段不自动加入计划任务，避免无人值守改动数据。

### 5.9 部署安全检查

新增只读命令 `python manage.py security_check`，逐项输出“通过/警告/失败”：

| 检查项 | 说明 |
|---|---|
| `DEBUG` 是否为关闭 | 生产启动脚本必须关闭 |
| `DJANGO_SECRET_KEY` 是否足够长且非占位值 | 复用现有校验 |
| `ALLOWED_HOSTS` 是否无通配符 | 防止主机头攻击 |
| 数据目录是否存在、是否可写 | 数据库、密文、密钥、备份 |
| 主密钥文件权限 | 仅当前用户可读写（尽力检查） |
| 备份文件权限 | 同上 |
| 最近备份时间 | 超过 7 天给警告 |
| 磁盘剩余空间 | 低于阈值给警告 |
| 审计保留配置 | 是否在合理范围（30–3650 天） |
| HTTPS/安全 Cookie | 当前未启用时提示留到局域网阶段 |

命令只读，不修改配置或数据；退出码：全部通过或仅警告为 0，存在失败项为 1。

### 5.10 系统状态接口

- 管理员接口返回：应用版本、数据库大小、密文文件数量和总大小、最近备份时间、磁盘剩余空间、审计记录数量、保险箱锁定状态。
- 不返回路径、密钥、内容或账号密码。
- 主页和安全检查页面使用该接口。

## 六、核心流程

### 6.1 查询审计

1. 管理员打开“审计日志”。
2. 默认显示最近 50 条。
3. 可按操作人、操作、结果和日期筛选。
4. 点击某条记录展开安全的结构化细节。
5. 本次查询写入 `audit_viewed`（含筛选条件摘要，不含敏感值）。

### 6.2 创建备份

1. 管理员打开“备份与恢复”。
2. 输入备份口令（至少 12 位）并确认；页面提示“口令不会保存”。
3. 系统检查磁盘空间，创建数据库快照，复制密文和主密钥文件，生成清单。
4. 压缩并整体加密为 `.efbak`，写入 `data/backups/`。
5. 计算备份包 SHA-256，写入备份记录和审计记录。
6. 页面显示文件名、大小、耗时和“请把备份包复制到另一块硬盘/另一台电脑”的提醒。

### 6.3 验证备份

1. 管理员在备份列表点“验证”。
2. 输入备份口令。
3. 系统解密到临时目录并校验清单和哈希。
4. 显示“验证通过”或具体失败原因。
5. 删除临时文件；更新备份记录和审计记录。

### 6.4 恢复备份

1. 管理员关闭服务器窗口。
2. 在服务器上运行 `scripts/restore-backup.ps1`，选择备份文件。
3. 输入备份口令，等待校验。
4. 核对显示的备份时间、版本和数量。
5. 输入 `RESTORE` 确认。
6. 系统自动保存当前数据副本，然后替换。
7. 启动服务器，登录、解锁并抽查条目。
8. 确认无误后再考虑清理 `pre-restore-时间/`；系统不会自动删除。

### 6.5 备份提醒

1. 管理员登录后，主页读取系统状态。
2. 超过 7 天没有成功备份时显示黄色提醒。
3. 点击提醒进入备份页面。

### 6.6 审计清理

1. 管理员或运维人员运行 `prune_audit --dry-run` 查看数量。
2. 确认后运行 `prune_audit`。
3. 系统删除到期记录并写入清理审计。
4. 页面只显示剩余记录，不提供删除按钮。

## 十、安全要求

| 编号 | 要求 | 说明 |
|---|---|---|
| S7-01 | 审计不含秘密 | 不记录密码、主密码、密钥、明文内容、原始文件名 |
| S7-02 | 审计只增不改 | 网页不提供修改/删除；清理只按保留期 |
| S7-03 | 管理员限定 | 审计、备份、系统状态仅管理员可见 |
| S7-04 | 备份口令不落地 | 不写配置、数据库、日志、审计或命令行历史 |
| S7-05 | 备份整体加密 | AES-256-GCM + Argon2id；清单和文件内容都不可见 |
| S7-06 | 完整性校验 | 创建和验证都校验 SHA-256；恢复前必须验证 |
| S7-07 | 恢复防误操作 | 服务器必须停止；输入 `RESTORE`；自动安全备份；失败回滚 |
| S7-08 | 不静默覆盖 | 恢复前显示备份信息并要求确认；旧数据保留 |
| S7-09 | 限速 | 备份创建/验证限制频率，避免口令暴力尝试 |
| S7-10 | 磁盘检查 | 备份和恢复前检查剩余空间 |
| S7-11 | 权限 | 备份文件和主密钥文件权限尽量限制为当前用户 |
| S7-12 | 日志脱敏 | 新增日志沿用现有脱敏过滤器，不记录口令 |
| S7-13 | 错误信息 | 不向页面返回服务器路径、堆栈或内部细节 |
| S7-14 | 版本兼容 | 恢复时检查格式版本；应用版本不同需显式放行 |
| S7-15 | 网络边界 | 默认仍只监听 `127.0.0.1`；开放局域网需单独确认 |

## 十三、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 备份口令丢失 | 备份包无法打开 | 创建时反复提示；文档说明与主密码分开保管；不保存口令 |
| 主密码丢失 | 恢复后仍无法解密内容 | 备份界面明确“四件套”；建议离线保存主密码 |
| 备份时数据正在变化 | 数据库与密文不一致 | 使用 SQLite 在线备份快照；创建期间仍可读取，但以快照为准 |
| 磁盘空间不足 | 备份失败或写坏文件 | 创建前检查 1.5 倍空间；先写临时文件，成功后再改名 |
| 恢复误操作 | 覆盖当前数据 | 服务器停止检查、输入 `RESTORE`、自动安全备份、失败回滚 |
| 审计表过大 | 查询变慢、数据库变大 | 180 天保留、索引、分页、清理命令 |
| 审计写入失败 | 缺少记录 | 记录警告日志；不阻断业务；安全检查和日志可发现 |
| 备份包被拿走 | 数据泄露 | 整体 AES-256-GCM 加密；口令不落地 |
| 管理员滥用查询 | 隐私风险 | 查询本身留痕；普通用户不可见 |
| 恢复后忘记锁定状态 | 误以为可直接查看 | 恢复后强制锁定，必须重新输入主密码 |

### 15.2 审计

- 新增 `AuditEvent` 模型和 `record_audit()` 辅助函数；操作人、角色、来源地址、请求编号自动补齐，写入失败只记警告日志，不阻断业务。
- 审计动作清单覆盖登录、首次设置、保险箱初始化/解锁/锁定、用户管理、用户组、条目、授权、文字/文件内容、备份和审计清理。
- 登录失败、解锁失败、永久删除密码错误等失败操作也会记录，结果分为成功、失败、被拒绝。
- 审计接口：
  - `GET /api/v1/admin/audit/`：按关键词、类别、具体操作、结果、日期筛选，50 条/页。
  - `GET /api/v1/admin/audit/options/`：返回类别、动作和结果选项。
  - 每次查询写入 `audit_viewed`。
- 普通用户访问审计、备份、系统状态接口统一返回 404。
- 新增 `prune_audit` 命令：支持 `--days`、`--dry-run`；实际清理后写入 `audit_pruned`。
- 前端新增“审计日志”页面：筛选、分页、展开安全详情；详情不显示请求原文。

### 15.3 加密备份

- 新增 `.efbak` 格式：
  - 文件头：`EFB1` 魔数、格式版本、Argon2id 盐和参数、基础 nonce、总大小。
  - 分块 AES-256-GCM 加密，每块独立 nonce 和认证标签；截断、篡改或口令错误都会拒绝。
- 备份包解密后是 ZIP：`manifest.json`、`db/db.sqlite3`、`keys/master.key.json`、`objects/*.vault`。
- 数据库使用 SQLite 在线备份接口生成一致性快照；文件和清单均记录 SHA-256。
- 创建前检查磁盘空间（至少 1.5 倍）；同一时间只允许一个备份任务；文件先写临时文件再改名。
- 备份口令至少 12 位，不写入配置、数据库、日志、审计或命令行历史。
- 备份接口：
  - `POST /api/v1/admin/backups/`：创建备份，限速 10 次/分钟。
  - `GET /api/v1/admin/backups/`：分页列表、最近备份摘要和提醒状态。
  - `POST /api/v1/admin/backups/{id}/verify/`：验证口令和完整性，限速。
- 前端新增“备份恢复”页面：创建、列表、验证、恢复说明；主页显示备份状态和到期提醒。
- 不提供网页删除或下载备份；备份文件由服务器操作员在 `data/backups/` 管理。

### 15.4 恢复

- 新增 `restore_backup` 管理命令和 `scripts/restore-backup.ps1` 包装脚本。
- 恢复前检查：
  - 服务器端口未监听（默认 8000）；
  - 备份口令正确；
  - 格式版本、清单结构、文件大小和 SHA-256 全部匹配；
  - 应用版本不同默认拒绝，可用 `--allow-version-mismatch` 显式放行。
- 恢复过程：
  1. 显示备份时间、版本和数量；
  2. 非 `--yes` 时必须输入 `RESTORE`；
  3. 把当前数据库、主密钥和密文复制到 `data/backups/pre-restore-时间/`；
  4. 替换数据库、主密钥和密文目录；
  5. 任一步失败自动回滚；
  6. 成功后写入 `backup_restored` 审计，保险箱保持锁定。
- `--skip-port-check` 只用于自动化测试；普通脚本不暴露该参数。
- 恢复会把数据库恢复到备份时点，备份之后的审计记录随当前数据库一起被替换；当前数据库完整保存在 `pre-restore-时间/`，需要时可从那里查询。

### 15.5 安全加固

- 新增只读命令 `security_check`，检查 10 项：DEBUG、Django 密钥、允许的主机名、数据目录、主密钥权限、最近备份、磁盘空间、审计保留期、HTTPS 准备、前端构建产物。
- 命令全部通过或仅警告时退出码为 0；存在失败项时退出码为 1。
- 新增 `GET /api/v1/admin/system/status/`：版本、数据库大小、密文数量和大小、磁盘剩余、审计数量、保险箱状态、备份摘要；不返回路径或秘密。
- 主页显示磁盘剩余和备份状态。
- 按 D7-7 A，本阶段未开放局域网，监听地址仍为 `127.0.0.1`；HTTPS 检查项给出警告。
