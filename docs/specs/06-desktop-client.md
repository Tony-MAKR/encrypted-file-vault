> **一句话**：给 Windows 电脑做一个桌面客户端——双击打开一个独立窗口，连接到现有服务器，使用同一套登录、条目、授权、加密查看和下载功能；不用每次打开浏览器找地址。
>
> **数据安全说明**：桌面客户端只是“窗口”，不会复制数据库、密钥或密文到每台电脑。所有数据仍保存在运行服务器的主机上；卸载客户端不会删除服务器数据。现有账号、条目、授权和加密内容全部保留。

---

## 一、本阶段目标

1. 提供 Windows 10/11 桌面客户端，可安装、启动、卸载。
2. 首次启动可以填写服务器地址，并测试连接；之后记住地址。
3. 桌面窗口加载与网页端相同的界面，登录后功能与网页一致。
4. 桌面客户端不保存登录密码，不复制数据库、主密钥或密文文件。
5. 启用桌面外壳的安全设置：禁用 Node 集成、启用上下文隔离和沙箱、限制导航、外部链接交给系统浏览器。
6. 后端能够直接提供打包后的网页资源，桌面客户端和浏览器打开同一个服务器地址。
7. 提供 Windows 安装包和免安装压缩包，附版本号、SHA-256 校验值和安装说明。
8. 保持第 1–5 阶段功能不变；本阶段不改变加密、密钥、授权或数据结构。

## 二、前置状态与硬约束

- 第 5 阶段已验收，网页端功能完整；真实数据库已有账号、条目、授权和加密内容，必须保留。
- 本阶段**不改数据库结构**；如果需要新的桌面配置，只保存在客户端本机。
- 服务器仍只在本机使用；局域网/HTTPS 在第 7 阶段。桌面客户端默认连接 `http://127.0.0.1:8000`，不要用它连接不可信网络。
- 桌面客户端只作为外壳，不内置 Python 后端、不复制数据库和密钥。
- 所有权限和加密仍由服务器执行；桌面端不能绕过网页端的授权检查。
- 不保存登录密码；不把密码、主密码或密钥写入客户端配置、日志或安装包。
- 不引入远程代码加载；生产环境不打开开发者工具。
- 继续使用现有 React/TypeScript/Vite 前端和第 4 阶段后端，不重新实现业务功能。

## 三、需要你拍板的关键决定

### 3.1 D6-1：桌面外壳用什么技术？

| 选项 | 像什么 | 优点 | 缺点 |
|---|---|---|---|
| **A. Electron（推荐）** | 用一个自带浏览器内核的成熟外壳包住现有网页 | 最成熟；Windows 安装包和更新资料多；与现有 Node/React 工具链一致；开发风险最低 | 安装包较大（约 80–150 MB）；内存占用较高；必须严格关闭 Node 集成，否则安全风险高 |
| B. Tauri | 用 Windows 自带的 WebView2 当外壳，Rust 做底层 | 安装包小、内存低、攻击面较小；长期维护成本可能更低 | 需要 Rust 工具链和 C++ 构建环境；贡献门槛高；Windows 打包和问题排查更复杂 |
| C. PWA / Edge 应用模式 | 把网页“安装”成浏览器快捷应用 | 不用安装包；开发和分发最简单 | 依赖 Edge/Chrome；桌面集成弱；不算真正的独立桌面软件；离线仍不可用 |

**推荐：A（Electron）。**

说明：

- 本次桌面端只是加载现有网页，不需要复杂原生功能；Electron 的风险主要来自错误配置，可以通过关闭 Node 集成、上下文隔离、沙箱和导航限制控制。
- 现有代码是 React + TypeScript + Vite，Electron 与现有构建链最匹配，能降低本阶段失败风险。
- 如果你更在意安装包体积和内存，可以选 B；代价是需要额外安装 Rust/C++ 构建环境，打包和后续维护更复杂。
- 无论选 A 还是 B，桌面端都不应内置后端或复制密钥。

### 3.2 D6-2：桌面客户端如何连接服务器？

| 选项 | 像什么 | 优点 | 缺点 |
|---|---|---|---|
| **A. 只做客户端，连接已有服务器（推荐）** | 每台电脑装一个“窗口”，数据都放在办公室主机 | 数据只有一份；符合局域网多人使用；卸载客户端不影响数据；升级客户端简单 | 必须先启动服务器；客户端电脑需要能访问服务器地址 |
| B. 客户端内置后端，单机即用 | 每台电脑装一整套保险箱，数据在各自电脑上 | 不需要单独启动服务器；单机使用方便 | 多人共享困难；每台电脑都存一份数据和密钥；打包 Python/Django 复杂；备份容易分散 |
| C. 两者都做 | 本机可内置，其他电脑连服务器 | 覆盖单机和多人 | 两套启动/更新/备份逻辑，本阶段工作量明显增加 |

**推荐：A（只做客户端，连接已有服务器）。**

说明：

- 第 0 阶段已确认“同一局域网多人使用”，数据应集中在主机，桌面客户端不应各自保存一份。
- 服务器继续用现有 `scripts/dev.ps1` 启动；第 7 阶段再做局域网/HTTPS 部署。
- 客户端只保存服务器地址和窗口设置，不保存数据库、主密钥、密文或密码。
- 如果以后需要“单机一键版”，可以再单独做打包，不影响本阶段。

### 3.3 D6-3：网页资源由谁提供？

| 选项 | 像什么 | 优点 | 缺点 |
|---|---|---|---|
| **A. 后端直接提供打包后的网页（推荐）** | 服务器既管数据，也把网页发给浏览器和桌面窗口 | 桌面和浏览器打开同一个地址；同源，登录 Cookie/CSRF 最简单；部署只需启动一个服务 | 需要给后端增加静态文件服务（例如 WhiteNoise）；前端构建产物要随服务器部署 |
| B. 桌面客户端内置网页资源，只连 API | 每个客户端自带网页文件，服务器只提供数据 | 服务器不需要提供静态网页；桌面端可离线显示外壳 | 跨域 Cookie/CSRF 配置复杂；浏览器用户仍需要另一套网页；客户端和服务器版本容易不一致 |
| C. 单独用 Nginx 等提供网页 | 另雇一个“前台”专门发网页 | 生产环境性能好、职责清晰 | 多一个部署组件和配置；第一版本机使用过于复杂 |

**推荐：A（后端直接提供打包后的网页）。**

说明：

- 当前前端是 Vite 开发服务器；正式使用时需要把构建产物交给后端提供。
- 同源后，桌面窗口和浏览器都访问 `http://127.0.0.1:8000/`，Cookie、CSRF、下载和 404 行为保持一致。
- 计划引入成熟的 `WhiteNoise` 静态文件服务；它只负责发静态资源，不参与加密和权限。
- React 路由需要 SPA 回退：非 API、非静态文件的页面请求返回 `index.html`；`/api/` 继续走后端接口。
- 开发环境继续使用 Vite 5173，不强制改变开发流程；生产/桌面使用后端地址。

### 3.4 D6-4：安装包怎么发布？

| 选项 | 像什么 | 优点 | 缺点 |
|---|---|---|---|
| **A. 安装包 + 免安装压缩包，暂不购买代码签名证书（推荐）** | 提供“安装版”和“解压即用版”，附校验值 | 用户选择多；发布成本低；适合当前阶段 | Windows SmartScreen 可能提示“未知发布者”；需要用户核对 SHA-256 |
| B. 购买代码签名证书并签名 | 给安装包办一张“身份证” | 减少 SmartScreen 警告；更正式 | 证书需要持续费用和身份审核；第一版增加采购流程 |
| C. 只提供免安装压缩包 | 解压后双击即可 | 最简单；不写注册表 | 没有开始菜单/卸载入口；普通用户容易找不到程序 |

**推荐：A（安装包 + 免安装包，暂不购买证书）。**

说明：

- 本阶段先保证可安装、可卸载、可校验；代码签名可在开源发布前或正式部署时再采购。
- 安装包使用 Windows 常见安装器；卸载只删除客户端文件，不删除服务器数据。
- 每个发布文件提供 SHA-256 校验值；安装说明写明 SmartScreen 提示的原因和核对方法。
- 如果本项目会正式发给不熟悉电脑的同事，可以选 B；需要提前准备证书预算和审核时间。

### 3.5 D6-5：客户端怎么更新？

| 选项 | 像什么 | 优点 | 缺点 |
|---|---|---|---|
| **A. 手动更新（推荐）** | 客户端显示版本号；有新版本时用户下载安装包覆盖安装 | 简单、可控；不需要更新服务器和签名基础设施；不会自动拉取远程代码 | 用户需要手动下载；版本可能落后 |
| B. 内置自动更新 | 客户端自己下载并安装新版本 | 用户省事；版本统一较快 | 需要签名、更新清单、托管和回滚方案；安全要求高 |
| C. 完全不管更新 | 安装后永远不更新 | 最省事 | 安全修复和功能无法送达，不建议 |

**推荐：A（手动更新）。**

说明：

- 第一版桌面端不做自动下载和执行远程代码，降低供应链风险。
- 客户端“关于”页显示版本号和构建时间；后续可在第 8 阶段接入 GitHub Releases 的版本检查，但仍由用户确认安装。
- 升级前建议先备份服务器数据；卸载/覆盖安装不会删除服务器数据。

### 3.6 D6-6：客户端是否记住登录信息？

| 选项 | 像什么 | 优点 | 缺点 |
|---|---|---|---|
| **A. 不保存密码，只使用服务器会话（推荐）** | 每次打开窗口，已登录就继续；退出或会话过期后重新输入 | 不在客户端存密码；与网页行为一致；实现简单 | 会话过期后要重新输入；不能“一键登录” |
| B. 只记住用户名 | 下次打开自动填用户名，密码仍需输入 | 方便一点；风险较低 | 会暴露用户名；对安全帮助有限 |
| C. 用 Windows 凭据管理器保存密码 | 把密码交给 Windows 保险库 | 下次可以自动登录 | 增加凭据管理和解锁逻辑；电脑被他人使用时仍可能登录；第一版复杂 |

**推荐：A（不保存密码，只使用服务器会话）。**

说明：

- 登录仍由服务器完成；桌面窗口只保留服务器会话 Cookie。
- 退出登录会清除服务器会话；关闭客户端不等于退出登录，按第 2 阶段会话超时规则处理。
- 不在客户端配置、日志或本地存储中保存登录密码、主密码或密钥。

## 五、技术设计

### 5.1 桌面端架构（Electron 方案）

```text
Windows 桌面窗口
  → Electron 主进程（窗口、菜单、服务器地址配置、版本信息）
  → 受限渲染进程（加载服务器网页，禁用 Node 集成）
  → 服务器 http://127.0.0.1:8000/
      → Django API + 静态网页
      → 数据库、密钥、密文（数据只在服务器）
```

- 渲染进程只加载用户配置的服务器 origin。
- 主进程不向网页暴露文件系统、Shell 或任意 IPC；只提供必要的“获取版本/打开设置”最小接口。
- 不在渲染进程开启 `nodeIntegration`、`remote` 或任意预加载脚本能力。
- 外部链接（例如帮助文档）用系统默认浏览器打开，不在应用内导航到其他域名。
- 服务器地址保存在 Electron `userData` 目录的普通配置文件中；不包含密码或密钥。
- 客户端不缓存加密明文到磁盘；网页缓存由服务器安全响应头控制。

### 5.2 服务器静态网页

- 前端构建产物输出到 `frontend/dist`。
- 部署/启动脚本将构建产物收集到后端静态目录；后端使用 WhiteNoise 提供静态文件。
- 访问 `/` 返回 `index.html`；React 前端路由（如 `/admin/items/1`）刷新时也返回 `index.html`。
- `/api/v1/...` 继续由后端处理，不返回 SPA 页面。
- 生产模式下前端 API 基址使用同源地址；开发模式仍可用 `VITE_API_BASE_URL` 指向 5173。
- 桌面客户端与浏览器打开同一个地址，行为一致。

### 5.3 服务器地址配置

- 首次启动显示配置页：服务器地址输入框、默认值 `http://127.0.0.1:8000`、测试连接按钮。
- 只接受 `http://` 或 `https://`；禁止 `file:`、`javascript:`、`data:` 和带用户名密码的 URL。
- 测试连接调用 `/api/v1/health/`，显示服务器版本和连接结果。
- 保存后打开主窗口；设置页可以修改地址，修改后重新加载。
- 地址无效或无法连接时显示明确错误，不白屏。
- 本阶段不自动发现服务器；局域网发现留到后续。

### 5.4 安全设置（Electron）

- `nodeIntegration: false`
- `contextIsolation: true`
- `sandbox: true`
- `webSecurity: true`
- 禁止 `webview` 标签
- 只允许导航到配置的服务器 origin；其他导航阻止或交给系统浏览器
- `window.open` 统一拦截；外部链接只允许 http/https，并用系统浏览器打开
- 生产环境关闭开发者工具和菜单中的调试入口
- 设置严格 CSP（由服务器响应头提供；桌面端不额外放宽）
- 不使用自动更新下载执行（按 D6-5 选择）
- 不把服务器地址或版本信息写入包含敏感数据的日志

### 5.5 安装与卸载

- 安装包：Windows x64，支持 Windows 10/11。
- 安装位置、开始菜单快捷方式、桌面快捷方式（可选）、卸载入口。
- 卸载只删除客户端程序和客户端配置；明确提示“服务器数据不受影响”。
- 免安装包：解压后运行，不在系统写入安装信息。
- 版本号和构建时间显示在“关于”页。
- 发布文件附 SHA-256 校验值和简要安装说明。

## 六、核心流程

### 6.1 首次启动

1. 用户双击客户端。
2. 显示服务器地址配置页，默认 `http://127.0.0.1:8000`。
3. 点击“测试连接”，显示服务器是否可用和版本。
4. 保存后打开主窗口，加载服务器登录页。
5. 用户使用现有账号登录；桌面端不保存密码。

### 6.2 日常启动

1. 客户端读取上次服务器地址。
2. 连接成功：打开主窗口；如果服务器会话仍有效，直接进入主页；否则显示登录页。
3. 连接失败：显示错误、重试和“修改服务器地址”按钮。
4. 服务器未启动时，提示先启动服务器，不静默失败。

### 6.3 使用内容

- 桌面窗口中的条目、授权、查看、显示/复制密码、下载、回收站等操作与网页完全一致。
- 下载文件由系统默认下载目录/保存对话框处理；提示“下载后离开系统保护”。
- 外部链接用系统浏览器打开。
- 剪贴板操作仍由网页逻辑处理；桌面端不额外保存密码。

### 6.4 退出与卸载

- 退出登录：调用服务器退出接口，清除服务器会话，回到登录页。
- 关闭窗口：会话按服务器超时规则保留；再次打开时若会话有效可继续。
- 卸载：只删除客户端文件；服务器数据库、密钥、密文和备份不受影响。

### 6.5 更新

- “关于”页显示当前版本和“检查更新”说明。
- 用户从发布页下载新安装包，覆盖安装。
- 覆盖安装前建议备份服务器数据；客户端配置（服务器地址）保留。
- 不自动下载或执行未签名的远程代码。

## 十二、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Electron 配置不当 | 网页获得本机文件/命令能力 | 关闭 Node 集成、上下文隔离、沙箱、导航限制；安全清单检查 |
| 安装包过大 | 下载/安装慢 | 只打包必要文件；提供免安装包；后续可评估 Tauri |
| 未签名安装包触发 SmartScreen | 用户不敢安装 | 提供 SHA-256、安装说明；正式发布前评估代码签名 |
| 服务器未启动 | 客户端打不开内容 | 明确错误页、重试、启动服务器说明 |
| 客户端与服务器版本不一致 | 页面/API 不兼容 | 版本信息显示；升级前备份；后续版本检查 |
| 服务器地址填错或指向不可信主机 | 钓鱼/凭据风险 | 地址校验、连接测试、只允许 http/https；第 7 阶段 HTTPS |
| 桌面端缓存残留 | 共用电脑信息泄露 | 不保存密码；退出登录；按服务器会话超时；清理缓存说明 |
| 卸载误以为删数据 | 用户不敢卸载 | 卸载说明明确“服务器数据不受影响” |
| 静态文件路由拦截 API | 接口 404 | 严格区分 `/api/` 与 SPA 回退；测试覆盖 |
| 范围膨胀 | 阶段拖长 | 不做内置后端、自动更新、局域网、签名、多平台 |
