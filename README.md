# 加密文件管理系统

一个本地部署的加密文件与敏感信息管理系统的长期项目。管理员可以加密保存文件、网站账号、数据库密码等内容，并按用户组或单个用户授权；只有被授权的人可以查看和解密。

> **当前状态：第 1–6 阶段已验收通过；第 7 阶段“审计、备份与安全加固”的 spec 已写好，等待审阅。**
> 第 6 阶段完成了 Windows 桌面客户端、后端直接提供网页、安装包/免安装包和 SHA-256 校验；现有账号、条目、授权和加密内容都已保留。
> 可查询的审计界面和加密备份/恢复界面尚未实现，是第 7 阶段的内容。
> 现在系统只在本机使用，**不要开放到局域网或公网**；是否开放局域网会在第 7 阶段单独确认。

## 当前能做什么

- 首次使用时，在本机创建第一位管理员。
- 登录、退出、修改自己的密码。
- 管理员创建用户、停用/启用用户、重置临时密码、解锁账号、调整角色。
- 管理员创建用户组、批量添加/移出成员；有内容授权的组不能直接删除。
- 管理员创建文字或文件条目，并按用户组或个人授权。
- 管理员给条目设置一个分类和多个标签，用分类/标签/类型/状态筛选和搜索。
- 管理员给文字条目保存网址、账号、密码、秘密备注；内容保存前加密。
- 文字密码表单有客户端密码生成器；生成结果只填入表单，保存时才加密。
- 管理员上传文件；文件边接收边加密，磁盘上没有明文、原始文件名或后缀。
- 普通用户只能看到被授权的条目；未授权地址返回“找不到”，撤销后立即失效。
- 被授权用户查看文字内容、显示/复制密码，或下载解密后的文件。
- 管理员可以查看全部条目元数据，但不会仅因角色自动获得内容权限。
- 保险箱支持主密码初始化、解锁、手动锁定；服务器重启后自动锁定。
- 条目归档/恢复、所有权转移、有效访问人预览、删除到 30 天回收站并恢复。
- 回收站支持永久删除；必须重新输入登录密码，删除后不可恢复。
- 管理员主页显示条目、加密内容、回收站、用户和用户组数量，以及最近更新。
- Windows 桌面客户端可连接服务器，登录、查看、下载等功能与网页一致。
- 后端可以直接提供打包后的网页；浏览器和桌面客户端打开同一个地址。
- 可以生成 Windows 安装包、免安装压缩包、SHA-256 校验值和安装说明。
- 桌面客户端只保存服务器地址和窗口大小，不保存密码、主密码或密钥。
- 临时密码用户首次登录必须改密；改密前不能使用其他功能。
- 连续登录失败锁定、会话空闲/最长超时、停用或重置后旧会话立即失效。
- 密码使用 Argon2id 哈希；内容使用 AES-256-GCM 信封加密；关键操作写安全日志。
- 配置、密钥、数据目录与代码分离；真实 `.env` 和 `data/` 不进版本库。
- 后端测试、代码检查和前端构建可通过。

## 当前不能做什么

- 没有可查询的审计界面和加密备份/恢复界面，第 7 阶段加入。
- 没有分类管理页、密码历史、密码强度评分、文件类型黑名单设置界面。
- 没有深色模式、UI 组件库、手机 App 或公网访问。
- 桌面安装包未做代码签名，Windows 可能提示“未知发布者”；请核对 SHA-256。
- 没有自动更新、系统托盘、开机自启或多服务器配置。
- 没有 HTTPS、局域网部署和双因素认证；是否在第 7 阶段开放局域网会单独确认。
- 主密码不能修改，密钥轮换和找回尚未实现；主密码丢失即无法恢复内容。
- 请不要把唯一一份重要秘密只放在这个系统里；第 7 阶段才会加入完整备份/恢复界面。

## 环境要求

- Windows 10/11
- Python 3.12+（当前开发环境为 3.14.6）
- Node.js LTS + npm（当前开发环境为 Node 24.16 / npm 11.13）
- Git（可选，用于版本管理）

## 一键安装

在项目根目录打开 PowerShell，运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup-dev.ps1
```

脚本会：

1. 在 `backend/.venv` 创建独立 Python 环境（不改动系统 Python）。
2. 安装后端运行和测试依赖。
3. 生成随机密钥并写入 `.env`（不会显示、不会提交）。
4. 创建/升级本地 SQLite 数据库。
5. 安装前端依赖到 `frontend/node_modules`。

## 启动和首次设置

```powershell
powershell -ExecutionPolicy Bypass -File scripts/dev.ps1
```

会打开两个 PowerShell 窗口：

- 后端：`http://127.0.0.1:8000/api/v1/health/`
- 前端：`http://127.0.0.1:5173`

如果使用的是全新数据库，第一次打开前端时会出现“创建第一位管理员”页面：

1. 设置登录用户名、显示名和密码（至少 12 位）。
2. 点击“创建管理员”；成功后入口自动关闭。
3. 用刚创建的账号登录。
4. 建议再创建一个普通用户，验证“首次登录必须改密”的流程。

> 首次设置只接受来自本机的请求。设置完成后，即使数据库里还有停用用户，设置入口也不会重新开放。
>
> 当前这台电脑上的数据库已经完成到第 5 阶段的迁移，已有账号和条目，不会再次出现首次设置页。

关闭这两个窗口即可停止服务。

## 正式使用：浏览器 + 桌面客户端

平时不需要再开两个窗口，只启动服务器：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start.ps1
```

脚本会先构建网页，再让后端在 `http://127.0.0.1:8000` 同时提供网页和接口：

- 浏览器直接打开 `http://127.0.0.1:8000/`。
- 桌面客户端默认也连接这个地址。
- 登录 Cookie、CSRF、下载和 404 行为在浏览器与桌面端一致。
- 已构建过网页时，可以加 `-SkipBuild` 跳过构建。

## 桌面客户端

### 安装

在项目根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-desktop.ps1
```

完成后的文件在 `desktop/release/`：

| 文件 | 用途 |
|---|---|
| `EncryptedFileVault-Setup-0.6.0-x64.exe` | 安装版，带开始菜单、桌面快捷方式和卸载入口 |
| `EncryptedFileVault-Portable-0.6.0-x64.zip` | 免安装版，解压后运行 |
| `SHA256SUMS.txt` | 发布文件的 SHA-256 校验值 |
| `INSTALL.txt` | 安装说明 |

> 安装包没有购买代码签名证书，Windows SmartScreen 可能提示“未知发布者”。请先核对 `SHA256SUMS.txt`，再决定是否运行。

### 第一次启动

1. 先在服务器上运行 `scripts/start.ps1`。
2. 打开桌面客户端，填写服务器地址，默认 `http://127.0.0.1:8000`。
3. 点“测试连接”；成功后会显示服务器版本。
4. 点“保存并连接”，使用现有账号登录。
5. 地址填错或服务器未启动时，会显示错误页，可“重试连接”或“修改服务器地址”。

### 数据与卸载

- 桌面客户端只是窗口，**不复制数据库、密钥或密文**；数据仍只在服务器上。
- 客户端只保存服务器地址和窗口大小，不保存登录密码、主密码或密钥。
- 退出登录会结束服务器会话；关闭窗口不等于退出登录。
- 卸载只删除客户端程序和客户端设置，**不会删除服务器数据**。
- 下载文件时会弹出保存对话框；下载后文件离开系统保护，无法远程撤回。
- 升级为手动更新：下载新安装包覆盖安装，建议先备份服务器数据。

### 开发时运行桌面端

```powershell
cd desktop
npm start
```

需要先启动后端；桌面端会读取已保存的服务器地址，首次运行显示设置页。

## 第一次使用：设置主密码

第一次给条目添加加密内容时，管理员会看到“设置主密码”页面：

1. 主密码**不是登录密码**，只用于解锁服务器上的保险箱。
2. 至少 12 位，建议用 4 个不相关的词组成长短语。
3. 主密码不会保存在服务器、数据库或 `.env` 中；服务器重启后需要重新输入。
4. **主密码丢失后，所有加密内容永久无法恢复**，没有找回方式。
5. 主密码请离线保存（纸张 + 保险柜，或离线密码管理器），不要和备份放在同一块硬盘上。

需要一起保管的“四件套”：

- 数据库：`data/db/db.sqlite3`
- 密文文件：`data/vault/objects/`
- 主密钥文件：`data/keys/master.key.json`
- 主密码（只在你脑子里或离线记录中）

缺少任意一项，加密内容都可能无法恢复。第 7 阶段会加入加密备份/恢复界面；在那之前请自行备份这四项。

## 管理员忘记密码怎么办

如果还有另一名启用中的管理员，请让对方在“用户管理”里重置你的密码。
如果只有一名管理员，可以在运行服务的电脑上执行：

```powershell
cd backend
.venv\Scripts\python.exe manage.py changepassword 你的用户名
```

该命令需要服务器访问权限，不通过网页开放。被锁定的账号会在 15 分钟后自动解锁；也可以在“用户管理”里由另一名管理员解锁。

## 目录说明

```text
backend/       Django 后端（账号、用户组、授权、加密存储、网页静态服务、测试）
frontend/      React + TypeScript + Vite 前端
desktop/       Electron 桌面客户端（主进程、设置/关于/错误页、打包配置）
desktop/release/  安装包、免安装包、SHA-256 和安装说明（不进入 Git）
docs/          可行性研究、需求分析、阶段 spec、桌面安装说明
scripts/       Windows 安装/启动/检查/桌面打包脚本
data/          本地数据库、密钥、密文文件和日志（不进入 Git）
data/keys/     主密钥文件（只会保存被主密码包裹的主密钥）
data/vault/    加密文件密文（随机文件名，无原后缀）
data/backups/  数据库备份（不进入 Git）
.env           本地配置与 Django 密钥（不进入 Git）
```

第 1 阶段的空数据库已在切换到自定义用户表前备份到 `data/backups/` 下。当前数据库保留了你后来创建的账号、组、条目和授权；第 3 阶段新增了用户组/条目/授权表，第 4 阶段新增了加密内容表和删除状态字段，第 5 阶段新增了分类/标签字段，没有重建或修改现有账号。第 4 阶段迁移前备份位于 `data/backups/stage3-before-content-20261019-191120/`，其中包含迁移前后的账号校验值、各表数量和比对结果（不含明文密码或内容）。第 6 阶段不修改数据库结构，只新增桌面客户端和网页静态服务。

## 安全说明（第 6 阶段）

- 后端服务器只监听 `127.0.0.1`，不接受局域网访问。
- 日常启动脚本设置 `DJANGO_DEBUG=false`，错误页不显示代码细节。
- 后端用 WhiteNoise 提供前端构建产物，并设置 CSP：只允许同源脚本、样式和连接。
- `/api/` 响应禁止缓存；静态资源只来自 `frontend/dist`，数据库、密钥和密文不在静态目录中。
- 桌面端关闭 Node 集成，启用上下文隔离和沙箱；只允许导航到配置的服务器地址。
- 桌面端拦截 `window.open` 和外部导航；http/https 链接交给系统浏览器，其他协议一律阻止。
- 桌面端权限默认拒绝，只允许“复制密码”所需的剪贴板写入。
- 桌面端生产版本关闭开发者工具；不自动下载或执行远程代码。
- 桌面端只保存服务器地址和窗口大小，不保存登录密码、主密码、密钥或内容。
- 桌面下载使用系统保存对话框；下载后文件离开系统保护，无法远程撤回。
- 安装包未做代码签名，发布时提供 SHA-256；请核对后再安装。
- 密码使用 Argon2id 哈希；不保存、不记录明文登录密码。
- 内容使用 AES-256-GCM 信封加密：每条内容一把数据钥匙，主密钥只用于包裹数据钥匙。
- 主密码通过 Argon2id 派生开锁钥匙；主密钥文件只保存被包裹的主密钥，不保存主密码或明文主密钥。
- 主密钥解锁后只存在服务器内存；服务器重启后自动锁定，管理员需要重新输入主密码。
- 元数据（标题/说明）保持明文，便于搜索和管理；**不要在这些字段里写密码或敏感细节**。
- 文件边接收边加密，不生成明文临时文件；磁盘上的文件名随机，原始文件名和 MIME 类型加密保存。
- GCM 认证标签 + 明文 SHA-256 校验；篡改、截断或文件损坏时拒绝返回内容。
- 普通用户未授权、已归档、已删除内容统一返回 404；内容接口每次都重新检查权限。
- 管理员可以查看所有条目的管理元数据，但不会自动获得内容解密权；编辑已有内容还需要内容访问授权。
- 分类和标签是明文管理信息，用于搜索和筛选；**不要写密码或秘密细节**。
- 删除进 30 天回收站，可恢复；到期清理会删除密文和记录并写日志。
- 永久删除只允许回收站条目，必须重新输入登录密码；密码错误不删除，尝试限速。
- 解锁接口和永久删除接口都有限速；显示密码、复制密码、下载、内容保存、删除、恢复、永久删除和解锁都写安全日志，不含秘密。
- 密码生成器只在浏览器本地生成，不发送给服务器、不写日志、不自动保存。
- `.env`、`data/`、虚拟环境、`node_modules`、前端构建产物和桌面安装包都已被 `.gitignore` 忽略。
- 日志会隐藏 `password=`、`token=`、`Authorization: Bearer ...` 等敏感值；内容日志不记录明文、主密码、数据钥匙或原始文件名。
- 主密钥文件权限采用尽力设置；建议同时开启 BitLocker，并使用受限 Windows 账户运行服务。
- **绝对不要**把开发服务器改到 `0.0.0.0` 或开放到公网；本阶段还没有为局域网做安全加固。
