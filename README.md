# 加密文件管理系统

一个本地部署的加密文件与敏感信息管理系统的长期项目。管理员可以加密保存文件、网站账号、数据库密码等内容，并按用户组或单个用户授权；只有被授权的人可以查看和解密。

> **当前状态：第 1、2、3 阶段已验收通过；第 4 阶段“加密存储引擎”的 spec 已写好，等待审阅。**
> 当前本地数据库中已有你在验收时创建的账号；第 3 阶段只新增了用户组、条目元数据和授权表，现有账号和密码已保留。
> 真实文件内容、加密存储、审计界面和桌面客户端尚未实现，将按阶段逐步加入。
> 现在系统只在本机开发环境中使用，**不要开放到局域网或公网**。

## 当前能做什么

- 首次使用时，在本机创建第一位管理员。
- 登录、退出、修改自己的密码。
- 管理员创建用户、停用/启用用户、重置临时密码、解锁账号、调整角色。
- 管理员创建用户组、批量添加/移出成员；有内容授权的组不能直接删除。
- 管理员创建占位条目（标题、类型、说明），按用户组或个人授权。
- 普通用户只能看到被授权的条目；未授权地址返回“找不到”，撤销后立即失效。
- 管理员可以查看全部条目元数据，但不会仅因角色自动获得内容权限。
- 条目归档/恢复、所有权转移、有效访问人预览。
- 临时密码用户首次登录必须改密；改密前不能使用其他功能。
- 连续登录失败锁定、会话空闲/最长超时、停用或重置后旧会话立即失效。
- 密码使用 Argon2id 哈希保存；登录、账号管理、组和授权操作写入安全日志。
- 配置、密钥、数据目录与代码分离；真实 `.env` 不进版本库。
- 后端测试、代码检查和前端构建可通过。

## 当前不能做什么

- 不能上传真实文件、保存真实密码内容、加密、解密或下载。
- 没有可查询的审计界面、备份恢复界面和回收站。
- 没有桌面客户端、手机 App 或公网访问。
- 没有 HTTPS、局域网部署和双因素认证。
- 还不能把真实敏感资料放到当前版本中；当前条目只是权限测试占位。

## 环境要求

- Windows 10/11
- Python 3.12+（当前开发环境为 3.14.6）
- Node.js LTS + npm（当前开发环境为 Node 24.16 / npm 11.13）
- Git（可选，用于版本管理）

## 一键安装

在项目根目录打开 PowerShell，运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup-dev.ps1
```

脚本会：

1. 在 `backend/.venv` 创建独立 Python 环境（不改动系统 Python）。
2. 安装后端运行和测试依赖。
3. 生成随机密钥并写入 `.env`（不会显示、不会提交）。
4. 创建/升级本地 SQLite 数据库。
5. 安装前端依赖到 `frontend/node_modules`。

## 启动和首次设置

```powershell
powershell -ExecutionPolicy Bypass -File scripts/dev.ps1
```

会打开两个 PowerShell 窗口：

- 后端：`http://127.0.0.1:8000/api/v1/health/`
- 前端：`http://127.0.0.1:5173`

如果使用的是全新数据库，第一次打开前端时会出现“创建第一位管理员”页面：

1. 设置登录用户名、显示名和密码（至少 12 位）。
2. 点击“创建管理员”；成功后入口自动关闭。
3. 用刚创建的账号登录。
4. 建议再创建一个普通用户，验证“首次登录必须改密”的流程。

> 首次设置只接受来自本机的请求。设置完成后，即使数据库里还有停用用户，设置入口也不会重新开放。
>
> 当前这台电脑上的数据库已经完成第 2 阶段验收，已有账号，不会再次出现首次设置页。

关闭这两个窗口即可停止服务。

## 管理员忘记密码怎么办

如果还有另一名启用中的管理员，请让对方在“用户管理”里重置你的密码。
如果只有一名管理员，可以在运行服务的电脑上执行：

```powershell
cd backend
.venv\Scripts\python.exe manage.py changepassword 你的用户名
```

该命令需要服务器访问权限，不通过网页开放。被锁定的账号会在 15 分钟后自动解锁；也可以在“用户管理”里由另一名管理员解锁。

## 目录说明

```text
backend/       Django 后端（账号、用户组、授权、健康检查、测试）
frontend/      React + TypeScript + Vite 前端
docs/          可行性研究、需求分析、阶段 spec
scripts/       Windows 安装/启动/检查脚本
data/          本地数据库、日志和未来加密文件（不进入 Git）
data/backups/  数据库备份（不进入 Git）
.env           本地配置与随机密钥（不进入 Git）
```

第 1 阶段的空数据库已在切换到自定义用户表前备份到 `data/backups/` 下。当前数据库仍保留第 2 阶段创建的账号；第 3 阶段在 2026-10-19 只新增了 5 张用户组/条目/授权表，没有重建或修改现有账号。迁移前备份位于 `data/backups/stage2-before-groups-20261018-235738/`，其中包含迁移前后的账号校验值和比对结果（不含明文密码）。

## 安全说明（第 3 阶段）

- 后端开发服务器只监听 `127.0.0.1`，不接受局域网访问。
- 密码使用 Argon2id 哈希；不保存、不记录明文密码。
- 密码至少 12 位；连续失败 5 次锁定 15 分钟；管理员可解锁。
- 会话 Cookie 为 HttpOnly + SameSite=Lax；空闲 30 分钟、最长 8 小时后需要重新登录。
- 所有状态变更请求要求 CSRF 令牌；登录和首次设置也受保护。
- 账号停用、管理员重置密码会立即让该用户的旧会话失效；用户自己改密会保留当前会话、清理其他会话。
- 最后一名启用中的管理员不能被停用或降级；管理员不能停用自己或修改自己的角色。
- 首次设置只接受本机请求，成功后关闭。
- 有效权限始终由后端计算：条目所有者、个人授权、用户所在组的授权三者取并集；没有“拒绝”规则。
- 撤销组授权、撤销个人授权、移出组成员、停用账号都会在下一次请求立即生效，不使用长期权限缓存。
- 普通用户访问未授权或已归档条目返回 404，不能通过条目 ID 探测存在性。
- 管理员可以查看所有条目的管理元数据，但不会自动获得内容解密权；管理员显式给自己授权会写日志。
- 有内容授权的用户组不能直接删除，必须先撤销授权，避免一批用户突然失去访问。
- 当前条目**不包含真实文件或密码内容**；请不要放入真实敏感资料。
- `.env`、`data/`、虚拟环境、`node_modules` 都已被 `.gitignore` 忽略。
- 日志会隐藏 `password=`、`token=`、`Authorization: Bearer ...` 等敏感值；组和授权日志不记录内容或密码。
- **绝对不要**把开发服务器改到 `0.0.0.0` 或开放到公网；本阶段还没有为局域网做安全加固。
